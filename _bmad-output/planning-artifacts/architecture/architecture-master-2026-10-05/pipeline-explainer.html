MSc thesis · study design

Do pretrained deep models beat classical ML at recognising activities from WiFi CSI?

This page sets out how the experiments will run: what goes in, how each method is scored, and how we keep the comparison fair. Nothing has been measured yet, so there are no results here.

Own dataset: 19 recordings · 2 rooms · 4 classes (empty, sitting, standing, walking) · ~63k packets · 4 antennas × 234 subcarriers
The pipeline

From a recording to a score

Every method goes through the same steps. Only step 5 changes from method to method. That makes any difference in the final table come from the model, not from how the data was handled.

Load recordings

The saved CSI files, each labelled with room and activity.

Split by time

Each recording is cut into training, validation and test stretches, separated by a gap.

Clean the signal

Rescale the amplitude and optionally remove the hardware phase offset. We try several variants.

Cut into windows

Short runs of consecutive packets, e.g. 40 packets ≈ 8 s. Every method gets the same windows.

Model summarises

A pretrained model (kept frozen) or a set of classical signal features turns each window into numbers. Optionally, the best features are selected.

Simple classifier

SVM, KNN, random forest, logistic regression or a small neural net, trained on those numbers.

Score

Accuracy, macro-F1 and a confusion matrix on the test stretches.

The split

Why we split by time instead of at random

Neighbouring windows overlap almost completely. With a 40-packet window moving one packet at a time, two neighbours share 39 of their 40 packets. If windows are assigned to train and test at random, the test set ends up full of near-copies of training windows, and accuracy looks higher than it really is. We therefore keep training and test in separate stretches of each recording, with a gap between them that no window can cross.

We will also rerun the dataset paper's own method under both splits. The random split reproduces the published figures, and the time-block split shows how much they change when leakage is removed. That difference is a result in itself.

Fairness

Rules every method follows

Same data

Identical split, windows and recordings for every method.

Same classifier

The same small classifiers are trained on top of every model's output.

Frozen models

All pretrained models are used exactly as released, with no further training. Fine-tuning comes in the next phase.

Tune on validation only

Settings, and the best variant of each method, are chosen on validation. The test stretches are scored once, at the end.

Repeated runs

Each result is the mean ± standard deviation over several random seeds.

Reproducible

Every number in the table is saved with its exact settings and can be regenerated with one command.

Open points

What we need from you

Is the time-block split acceptable?

Training, validation and test stretches within each recording, separated by a 64-packet gap (about 13 s at 5 packets/s). Is this the right primary protocol for the thesis?

Do the saved recordings share one sample rate?

Some files were downsampled before saving (by 2, 3 or 5). If their final rates differ, the model might learn the rate rather than the activity, so we would add a check with equalised rates.

Data cleaning

Which cleaning steps should be applied, if any (e.g. removing outlier or noisy packets)? Each one becomes an option that can be switched on per experiment.
